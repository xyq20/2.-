# 快麦 ERP 有赞平台资料填写设计

## 1. 目标

在不重构现有抖音、淘宝、天猫、拼多多和小红书逻辑的前提下，新增独立的有赞平台适配器，完成“有赞资料”页签的类目、类目属性、SKU 价格库存、重量、库存扣减、配送方式和运费模板填写。

先完成有赞独立流程和真实浏览器验证；只有单平台验证无误后，才把有赞加入 `all` 全平台流程。

## 2. 范围与门禁

### 2.1 包含

- 新增 `youzan` 平台数据模型和 DOM 表单适配器。
- 在统一平台注册表、命令行和启动菜单中增加“有赞”独立入口。
- 从 Excel 读取类目路径、动态属性、价格和库存。
- 批量设置 SKU 价格、库存及固定重量 `1 kg`，并逐行回读。
- 设置商品总重量 `1 kg`、付款减库存、快递发货和品类对应运费模板。
- 完成不保存浏览器验证，再做只保存浏览器验证与保存后回读。
- 单平台验收通过后，将有赞按注册顺序加入 `all`。
- 铺货目标固定为“有赞 / NEIGBORL官方旗舰店”；预览只勾选并截图，正式模式才提交。

### 2.2 不包含

- 无铺货预览不点击选店弹窗的最终“确定”，不提交铺货。
- 不修改基础资料；有赞独立流程直接切换至“有赞资料”。
- 不借此重构其他平台或删除现有时序容错逻辑。
- 候选值不唯一时不猜选，而是停止并保留错误截图与报告。

## 3. 数据来源

### 3.1 类目

- 类目来源为 Excel “商品分类”，斜杠表示有序层级或具体化名称。
- 当前测试 Excel 为：`休闲裤 / 男士休闲直筒裤 / 工装休闲裤`。
- 有赞搜索词优先取 Excel 类目的第一段，当前商品搜索“休闲裤”。
- 搜索结果必须精确命中完整路径 `服装鞋包 > 男装 > 休闲裤`，再点击“确定”。
- 未来其他品类不写死叶子 ID；以 Excel 词和真实 DOM 完整路径精确匹配。

### 3.2 类目属性

- 保留 Excel 全部非空键值，等类目渲染后按页面实际标签匹配。
- 标题中用 `/` 分组的同义字段可作为页面标签别名，值中的斜杠表示候选顺序。
- 页面下拉值按精确文本选择；必填字段找不到可用候选则报错，不选“其他”代替。
- 货号取 Excel “货号/商家外部编码”。

### 3.3 价格、库存与重量

- SKU 价格依次从 Excel `价格 / 一口价 / 基本售价 / 商品价格 / 售卖价 / 售价` 的可用精确字段取值。
- SKU 库存取 Excel “数量”或“库存”，不把抖音专用的“现货库存”误当有赞库存。
- SKU 重量和商品总重量均固定为 `1 kg`。
- 价格必须大于 `0`，库存必须为非负整数。

## 4. DOM 执行流程

1. 切换到“有赞资料”，等待页签内容稳定。
2. 勾选商品类型“实物商品”，确认状态已选中。
3. 点击“修改类目”，在弹窗搜索 Excel 类目词，精确选择完整路径，确认后回读页面已选类目。
4. 等待类目参数重新渲染，再依 Excel 填写属性。
5. 在规格明细批量行依次填写价格、库存、重量 `1`，然后只点击一次“批量设置”。
6. 等待 SKU 表格更新，逐行回读价格、库存和重量；任一行不一致则禁止保存。
7. 填写商品总重量 `1`，选中“付款减库存”，勾选“快递发货”。
8. 按商品品类设置运费模板：
   - Excel 商品分类或商品标题含“裤”：选页面真实候选“T恤、裤子、饰品邮费模版”。
   - Excel 商品分类或商品标题含“外套/皮衣”：选页面真实候选“鞋子、皮衣、外套邮费模版”。
   - 无法唯一分类时停止，不保留页面旧模板。
9. 读取页面可见校验错误，保存前产出 JSON 报告和截图。

## 5. 保存与回读

### 5.1 不保存验证

- 用 `--platform youzan --no-save` 打开脚本专用 Chrome。
- 跑完全部填写与校验，保留 `youzan-before-save.json` 和截图。
- 不点击保存，不打开铺货选店弹窗。

### 5.2 只保存验证

- 不保存验证通过后，使用 `--platform youzan --save-only`。
- 只点击底部“保存”，通过页面成功提示或可证明的状态变化确认保存完成。
- 非全平台共享会话时，重新打开该商品的有赞页签，回读类目、SKU 价格/库存/重量、总重量、库存扣减、配送方式和运费模板。
- 任一关键值不符即作为保存失败，不将有赞加入 `all`。

## 6. 全平台接入

仅当以下条件全部满足时，将有赞的 `enabled_in_all` 设为 `true`：

- 数据解析和 DOM fixture 单元测试通过。
- 有赞独立不保存浏览器测试通过。
- 有赞独立只保存浏览器测试通过，且重开回读一致。
- 全平台启动菜单和注册表测试更新。

有赞加入 `all` 后继续复用同一 Playwright context、page 和编辑 drawer；前一平台保存确认后直接切换到“有赞资料”，不刷新页面、不重复填写基础资料。

正式 `--save` 模式打开“铺货到店铺”后，只选“有赞”平台且只勾选 `NEIGBORL官方旗舰店`，回读勾选状态完全一致后才点击最终“确定”。`--youzan-publish-preview` 执行相同的精确选择，截图后安全关闭弹窗，不提交。

## 7. 错误处理和可观测性

- 每个阶段写明日志：打开页签、类目、属性、SKU 批量设置、库存/配送、运费模板、保存前校验、保存、保存后回读。
- 异常时保存当前页面截图和阶段名，错误消息不只报“找不到元素”。
- 页面重渲染后重新取 locator，不复用失效 DOM 引用。
- “批量设置”只点击一次，用 SKU 行回读作为成功凭证，避免重复填写。
- 保存后的页面显示不作为唯一成功凭证，必须配合保存结果和重开回读。

## 8. 预计文件

- `youzan_data.py`：Excel 字段快照和类目路径。
- `youzan_form_listing.py`：有赞 DOM 表单填写、校验和保存后回读。
- `platform_registry.py`：先注册为可独立运行但不进入 `all`，验收后开启 `enabled_in_all`。
- `kuaimai_erp.py`：读取、调度、报告、保存与回读接入。
- `run.command`：增加有赞菜单和三种模式；正式铺货仍需输入 `PUBLISH` 确认。
- `tests/test_youzan_data.py`、`tests/test_youzan_form_listing.py`、现有注册表/启动器/主流程测试。

## 9. 验收标准

1. 当前测试 Excel 能稳定选中 `服装鞋包 > 男装 > 休闲裤`。
2. 页面类目属性按 Excel 填写，必填项无未处理错误。
3. 每个 SKU 的价格和库存等于 Excel，重量等于 `1`。
4. 商品总重量等于 `1`，库存规则为“付款减库存”，配送方式包含“快递发货”。
5. 当前裤装商品选中“T恤、裤子、饰品邮费模版”；外套商品选中“鞋子、皮衣、外套邮费模版”。
6. 不保存测试不产生保存或铺货写操作。
7. 只保存测试产生真实保存成功凭证，重开回读的关键值全部一致，且不铺货。
8. 满足以上标准后，有赞加入 `all`，且全平台流程不刷新、不重复基础资料。
9. 铺货预览只勾选“有赞 / NEIGBORL官方旗舰店”，报告 `submitted=false`，且不点击最终“确定”。

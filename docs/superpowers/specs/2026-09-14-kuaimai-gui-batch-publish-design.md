# 快麦一键铺货 GUI 与批量执行设计

日期：2026-09-14

## 背景与目标

为非技术同事提供一个 macOS 原生窗口，用于从共享盘 `products` 目录选择商品并启动现有快麦铺货脚本。窗口需要支持单选执行，也需要支持多选后按顺序批量执行；平台填写、保存、铺货、登录恢复、截图、回读和运行报告继续由现有 `kuaimai_erp.py` 负责。

换到另一台 Mac 时，使用项目内新的 `run-gui.command` 启动器完成虚拟环境和 Python 依赖准备。GUI 不保存密码、Cookie、Token 或其他凭证；新 Mac 首次运行沿用现有脚本的登录流程。

## 用户流程

1. 同事先在 Finder 中挂载共享盘。
2. 双击 `run-gui.command`。
3. GUI 自动发现共享盘中的 `products` 目录，并列出其中包含 `产品信息.xlsx` 的一级商品文件夹。
4. 同事可以勾选一个商品后点击“开始一键铺货”，也可以勾选多个商品后批量运行。
5. GUI 按列表顺序串行启动任务，每个商品独立调用一次现有 Python 主程序。
6. 窗口显示当前商品、已完成数量、失败数量、未启动数量和子进程输出；任务结束后显示汇总及报告目录。

“开始一键铺货”对应现有全平台 `--save` 流程，点击按钮即视为对所选商品执行真实保存和铺货的明确授权。GUI 不再重复实现或模拟平台操作，也不把后台任务提交误显示为平台最终完成；成功状态沿用现有脚本的退出码和结果报告语义。

## 方案与边界

### 选择 Tkinter

采用 Tkinter 原生 GUI，不引入 Gradio 或本地 Web 服务。这样可以用 macOS 的窗口交互，并将迁移步骤限制为复制项目、挂载共享盘、双击启动器。Tkinter 不进入 `requirements.txt`；启动器会在导入失败时给出明确安装提示。

### 共享盘发现

GUI 首先检查当前配置的共享盘路径，再检查 macOS `/Volumes` 下的常见路径，包括当前项目约定的 `共享文件/谭/products` 以及挂载卷内的 `products` 目录。目录不存在时，窗口允许同事通过系统目录选择器手动指定一次；刷新时重新扫描并保持当前可用选择。

只展示包含 `产品信息.xlsx` 的一级子目录。文件夹名作为商品显示名，商品实际执行路径始终由发现结果得到，不根据文件夹名拼接或猜测 Excel 路径。

### 任务执行

GUI 使用当前项目虚拟环境中的 Python，串行调用：

```text
python kuaimai_erp.py --excel-url <商品目录>/产品信息.xlsx --platform all --save
```

每个商品使用独立子进程，避免多个商品同时争用专用 Chrome profile、登录状态和输出目录。GUI 读取子进程标准输出和标准错误并显示到日志区域；现有脚本继续写入 `output/kuaimai/runs/<timestamp>/`。

单选和多选共用同一执行路径：单选只是队列长度为 1，多选则按复选框当前顺序逐个执行。执行过程中禁用选择和开始按钮，提供停止后续任务的操作；停止只阻止尚未启动的商品，不强制杀死当前正在进行的浏览器任务。

### 失败和结果

- 商品输入校验失败、脚本返回业务错误或未预期错误时，该商品标记为“失败”，保留输出，并继续执行后续已选择商品。
- 用户停止后，尚未启动的商品标记为“未启动”，不创建子进程。
- 子进程返回 0 时标记为“已完成/已提交”，具体是已保存、已铺货或后台任务已提交，以现有运行报告为准。
- 批量结束后显示成功、失败、未启动清单和每个商品的报告根目录，不重复启动失败商品。

GUI 不复制、修改或迁移 `output/kuaimai/auth-state.json` 和 Chrome profile。新 Mac 需要按现有流程重新建立本机登录状态；凭证继续由项目既有钥匙串/会话机制管理。

## 组件边界

### `kuaimai_gui.py`

包含可独立测试的共享盘发现、商品目录校验、子进程参数组装和批量队列控制，以及 Tkinter 窗口层。窗口层只负责选择、状态和日志展示，不导入平台表单实现。

### `run-gui.command`

负责切换到项目目录、创建 `.venv`、安装 `requirements.txt`、检查 Tkinter，然后启动 `kuaimai_gui.py`。它不进入原有终端菜单，也不要求同事输入命令行参数。

### 现有 `kuaimai_erp.py`

保持平台业务逻辑、登录恢复、保存/铺货门禁和结果回读不变。GUI 只通过公开 CLI 参数调用它。

## 验证

1. 单元测试覆盖：共享盘候选路径发现、只筛选有效商品目录、单选/多选参数顺序、停止后续任务状态和失败后继续策略。
2. 启动器测试覆盖：虚拟环境存在时正确启动 GUI，缺少 Tkinter 时输出迁移提示。
3. 本地 dry-run/模拟子进程验证 GUI 不会重复启动、单选只执行一个、多选按顺序执行，且不改动用户当前已有工作区文件。
4. 真机验收时先使用一个商品确认登录、窗口日志和现有报告，再选择多个商品验证串行批量和失败汇总。

## 明确不做

- 不重写任何平台铺货逻辑。
- 不在 GUI 中保存账号密码、Cookie、Token、Webhook 或密钥。
- 不并发执行多个商品。
- 不自动复制旧 Mac 的认证状态到新 Mac。
- 不在 GUI 中增加新的平台店铺配置页面；店铺仍由现有脚本配置控制。

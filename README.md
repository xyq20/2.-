# 快麦 ERP 自动铺货

该程序读取产品文件夹中的 `产品信息.xlsx`、1:1 主图、3:4 主图、详情页图和 SKU 图，自动编辑快麦商品中心的基础资料，并执行已实现平台的资料填写与铺货。

当前默认产品：

`smb://gongxiang/共享文件/谭/products/绿巨人+NGBL-10588/产品信息.xlsx`

执行顺序：

1. 读取 Excel 第二行商品名称、货号和“吊牌价/价格/基本售价”。
2. 打开 `https://erp.superboss.cc/index.html#/index/`，通过 ERP 首页“快麦通”入口完成单点登录。
3. 优先调用快麦 `/item/base/page` 同源 API 确认目标商品，DOM 查询作为兜底。
4. 打开“编辑 -> 基础资料”，填写商品名称并同步图片；SKU 图已有真实图时跳过，只有快麦默认纯白占位图会被替换。
5. 将基本售价批量设置到全部 SKU。
6. 保存前复核款式编码、商品名称、图片数量、售价和页面校验错误。
7. 填写并复核抖音资料，保存后选择目标店铺；已铺货店铺自动跳过。
8. 点击外层“确定”，再点击“继续铺货”，最后回读铺货结果。

淘宝平台已完成真实填写、保存和“钊叔制”单店铺铺货验收：

1. 默认进入“修改类目”，搜索“休闲裤”，精确选择“男装 > 休闲裤”并确定；旧的动态“推荐 > 点击使用”逻辑保留为独立模式，可通过 `--taobao-category-mode recommended` 切换。
2. 按淘宝页面实际类目属性顺序匹配 Excel 字段和值；有候选时精确选择，只有平台明确支持自定义值时才直接填写 Excel 值，否则记录为跳过，避免出现“页面看似已填、保存后丢失”。
3. “面料”与“材质成分”读取各自独立的 Excel 字段；材质成分点击“添加”后逐行填写材质和含量。
4. “防水等级”和“适用年龄段”按运营规则保持空白。
5. 店铺中分类只填写“钊叔制”；所有平台统一按“逗号分组全选、斜杆为 OR”解析 Excel。斜杆候选先按 Excel 顺序匹配平台真实下拉项；都无匹配时再尝试 Excel 第一项，不支持自定义的组件记录为跳过。
6. 商品规格中只有一个“颜色”时不处理；出现重复时只取消最后一个“颜色”的勾选，不删除规格项。仅在页面与组件均确认该项已取消时，忽略对应的“规格名【颜色】重复”提示，其他校验错误仍会阻止保存。
7. 按 Excel 批量填写 SKU 价格、数量、是否加绒、SKU 分类和适用体型；页面新增的 SKU 下拉字段（如裤长、厚薄）也按同名 Excel 字段动态填写并记录每行回读值，然后点击“批量设置”。随后读取产品目录“尺码信息表”的唯一图片，裤子按尺码填写裤长，衣服按尺码填写衣长。
8. 填写一口价和商家编码，保留平台已生成的规格编码。
9. 按顺序设置库存扣减、保修服务、七天退货承诺、立刻上架和“钊叔制”运费模板；七天退货按稳定关键词定位，不依赖页面“可支持/必须支持”等易变化文案。
10. 普通预览流程强制不保存、不铺货。铺货弹窗可用
    `--taobao-publish-preview --allow-taobao-save-once` 单次预览：选择“淘宝”平台，
    取消其他店铺并且只勾选“钊叔制”，截图后关闭弹窗，不点击最终“确定”。
11. 获得单次真实铺货授权时使用 `--allow-taobao-publish-once`：完整复核后
    点击“保存并铺货到平台”，选择“淘宝”并只勾选“钊叔制”。
    淘宝在最终“确定”后直接提交并返回商品列表，不会像抖音那样再出现“继续铺货”。

天猫平台已接入正式填写、保存和单店铺铺货流程：

1. 选择页面推荐类目并按 Excel 精确填写品牌、货号、重要属性、腰型、SKU、尺码表、物流和售后字段。
2. 属性图片与 SKU 图按颜色规格值对应；页面为默认空白占位图时会替换为本地图片，真实图片会保留。
3. 保存并铺货时选择“天猫”平台，只勾选 `NEIGBORL批判家专卖店`；已铺货店铺不会重复提交。
4. 天猫正式流程不再需要 `--allow-tmall-publish-once`；使用 `--save-only` 可只保存、不铺货。

拼多多平台已接入填写与保存复核流程：

1. 优先使用页面唯一推荐类目；已有有效类目时保留，不猜选其他类目。
2. 类目属性按 Excel 与页面真实候选精确匹配；`裆部结构`无论 Excel 是否存在均保持空白。
3. 使用“批量设置”统一填写并逐行回读拼单价、单买价和库存；拼多多库存对应 Excel 的“库存/数量”，不使用抖音专用“现货库存”。
4. 固定选择“时段预售”，并将“支付成功后”设为 `15天`。保存并铺货时选择“拼多多”平台，只勾选 `NEIGBORL鞋服旗舰店`；已铺货店铺不会重复提交。

## 运行

### 一键新增链接（视频固定填法）

双击 `run.command` → **9 一键新增链接** → **2 保存，但不铺货**。选择 **1** 可先填写预览。

此入口只创建一个快麦基础商品：从当前产品 Excel 读取货号，商品名称固定填 `1`，上传产品目录第一张 1:1 主图；颜色填 `军绿色`；尺码点击“填充常用规格”，应用第一个默认模板（视频为 S/M/L/XL/2XL）；商品编码点击“批量生成”后直接确定默认规则（款式编码＋规格值）。价格、库存等保持页面默认 `0`，不另传 SKU 图或补全平台资料。创建后可再使用原基础资料/全平台流程完善商品。

保存按原程序默认选择“跳过同步”，需要同步 ERP 时显式传入 `--sync-erp`。同款已存在时跳过，不覆盖原商品；查重失败时停止；提交结果不确定时记录报告，不自动再次保存。保存后重新打开商品验证名称、主图、规格及编码，报告位于 `output/kuaimai/runs/<timestamp>/create-product-result.json`。

```bash
./run.command --create-product --dry-run
./run.command --create-product --no-save
./run.command --create-product --save-only
./run.command --create-product --save-only --excel-url '/其他产品/产品信息.xlsx'
```

直接调用 Python 时同时传入 `--platform base`；新增入口不会铺货到外部店铺。

首先在 Finder 中确认 `smb://gongxiang/共享文件` 已挂载。

双击 `run.command`，或在终端运行：

```bash
./run.command
```

`run.command` 是唯一启动器。双击后会在同一个终端依次选择运行平台和执行模式。

双击后可选择：平台（全平台流程、基础资料、抖音、淘宝、天猫、拼多多、微信小店、小红书或有赞）以及执行模式（仅填写/检查平台资料、保存但不铺货、保存并铺货）。

<!-- 平台选择与保存/铺货模式统一由 run.command 的终端菜单处理。 -->

选择“保存并铺货”时还必须输入大写 `PUBLISH`。单个平台不会改动基础资料；全平台选择“保存”或“保存并铺货”时，会在同一个商品编辑页先填写并保存一次基础资料，确认保存完成后直接切换下一个平台，不刷新网页、不重复查询或重开商品。淘宝仍保留一次性授权门禁；天猫、拼多多、微信小店、小红书和有赞会选择各自平台并只勾选配置的指定店铺。所有平台业务逻辑仍由同一个 `kuaimai_erp.py` 执行。

也可以直接传参数跳过菜单，适合自动化测试：

```bash
./run.command --platform tmall --no-save
./run.command --platform tmall --save-only
./run.command --platform tmall --save
./run.command --platform pdd --no-save
./run.command --platform pdd --save-only
./run.command --platform pdd --save
./run.command --platform wxsph --no-save
./run.command --platform wxsph --save-only
./run.command --platform wxsph --save
./run.command --platform wxsph --wxsph-publish-preview
./run.command --platform xhs --no-save
./run.command --platform xhs --save-only
./run.command --platform xhs --save
./run.command --platform youzan --no-save
./run.command --platform youzan --save-only
./run.command --platform taobao --save-only --allow-taobao-save-once
```

### 天猫、拼多多、微信小店、小红书、有赞填写与字段发现

菜单选择天猫的“仅填写/检查”模式时使用 `--platform tmall --no-save`：不会填写或保存基础资料，直接切换天猫资料，只填写并校验天猫资料，不保存天猫资料、不铺货。首次天猫页会等待五张产品图片都完成浏览器解码并连续两次检查稳定后，再按 3、2、1、4、5 的顺序替换，并点击产品信息内蓝色“发布”生成后续表单；该动作不点击底部保存或铺货。选择“保存，但不铺货”使用 `--platform tmall --save-only`；选择“保存并铺货”使用 `--platform tmall --save`，程序会在保存成功后选择天猫并只勾选 `NEIGBORL批判家专卖店`，完成提交和结果回读。天猫报告位于 `output/kuaimai/runs/<timestamp>/`。

菜单选择拼多多的“仅填写/检查”模式时使用 `--platform pdd --no-save`：不会填写或保存基础资料，直接切换拼多多资料，只填写并校验拼多多资料，不保存拼多多资料、不铺货；选择“保存，但不铺货”使用 `--platform pdd --save-only`；选择“保存并铺货”使用 `--platform pdd --save`，程序选择拼多多并只勾选 `NEIGBORL鞋服旗舰店`。

菜单选择小红书的“仅填写/检查”模式时使用 `--platform xhs --no-save`：不会填写或保存基础资料，直接切换小红书资料，再按 Excel `商品分类` 的 `/` 层级选择小红书类目；商品标题移除 `NEIGBORL`，填写货号和可精确匹配的类目属性，选择“全款预售模式 → 时段预售 → 付款后 15 天发货”，填写售价和库存后点击“批量设置”，并把小红书主图替换为本地 `3:4主图`。选择“保存，但不铺货”时使用 `--platform xhs --save-only`；选择“保存并铺货”使用 `--platform xhs --save`，程序选择小红书，只勾选 `钊叔的店`、`啊亮熟NEIGBORL的店`、`钊叔制NEIGBORL的店`、`老朱和NEIGBORL的店` 和 `NEIGBORL钊叔旁伦的店`。

菜单选择有赞的“仅填写/检查”模式时使用 `--platform youzan --no-save`：选择“实物商品”，根据 Excel `商品分类` 以接口返回的完整路径和 DOM 文本双重校验后选择类目，填写类目属性。下拉候选无精确匹配时直接填写 Excel 第一顺位值并回读；面料含百分比时解析成分，不含百分比时使用面料名。SKU 价格和库存来自 Excel，重量固定为 1，仅点击一次“批量设置”；并选择“付款减库存”、“快递发货”及对应品类的邮费模版。`--platform youzan --save-only` 仅保存不铺货，保存后会重新打开商品，回读类目属性、5 行 SKU、重量、库存扣减、配送方式和运费模版。`--platform youzan --youzan-publish-preview` 会保存资料、打开铺货弹窗，只勾选“有赞 / NEIGBORL官方旗舰店”并截图后关闭，不点击最终“确定”。单平台或全平台的“保存并铺货”模式才会在精确回读店铺勾选状态后点击最终“确定”。

微信小店（视频号）可使用 `--platform wxsph --no-save` 做填写预览，或使用 `--platform wxsph --save-only` 只保存、不铺货：按 Excel 精确匹配类目属性，填写售卖价、市场价和库存后只点击一次“批量设置”；随后点击“批量编辑发货”，选择“全款预售”和“买家付款后 n 天发货”，填写 `15` 并点击弹窗“确定”；商品重量固定为 `1`。材质含量为下拉框时选 `95%及以上`；材质成分文本按 Excel `棉（100%）` 填成 `棉100%`；独立百分比输入框只在对应 Excel 材质实际带百分比时填写，例如面料填 `100`、无百分比的里料保持空白。连续切换平台时，属性最长等待 `30` 秒，第 `12` 秒仍未出现则不刷新网页、重新激活页签一次，字段集合连续稳定 `0.75` 秒后才填写。保存前报告同时用微信小店只读 API 属性名与当前 DOM 表单标签交叉校验；保存成功后会在当前商品编辑页回读类目属性、售卖价、市场价、每行库存、每行发货方式和重量，全部一致才报告完成。`--wxsph-publish-preview` 会保存资料、打开铺货弹窗，只勾选“微信小店（视频号） / NEIGBORL钊叔制鞋服、NEIGBORL钊叔制造局”，截图后关闭，不点击最终“确定”。`--platform wxsph --save` 和全平台正式铺货会在同样的精确复核后提交这两家店铺；页面/API 结构发现仍可显式使用 `--inspect-only --no-save`。

每次运行的脱敏结果保存到 `output/platform-schema/<timestamp>/`，包含平台 schema、DOM 差异、`summary.json`、`run.log` 和本地验收截图。`partial` 或 `failed` 仍会先写报告再以业务错误退出，不代表已完整抓取。

首次会打开一个自动化专用的 Google Chrome，入口是快麦 ERP 首页 `https://erp.superboss.cc/index.html#/index/`。登录页出现且密码未保存时，运行终端会提示安全输入一次密码；密码只存入 macOS 钥匙串，不写入项目文件或日志。以后登录过期时，程序会自动回读密码、勾选协议并点击登录；若未录入或取消录入，会保留 20 分钟手工登录等待。

登录状态同时保存在 `output/kuaimai/chrome-profile/` 和 `output/kuaimai/auth-state.json`。后者专门保留 Chrome 正常关闭时会清理的会话 Cookie，后续运行会自动恢复。该文件包含本机登录凭证，请勿发送给他人。

针对快麦页面加载较慢的情况，默认等待时间已调整为：页面和保存 300 秒、每组图片上传 600 秒。编辑抽屉会等待加载遮罩消失并确认款式编码出现后，才开始填写。

> 双击 `run.command` 后必须先选择执行模式；选择“仅填写/检查”不会保存或铺货平台资料，也不会改动基础资料。微信小店同样支持“保存，但不铺货”和“保存并铺货”；单平台模式都不会填写基础资料。直接传命令行参数时，请显式指定 `--no-save`、`--save-only` 或 `--save`。

只检查 Excel 和图片目录：

```bash
./run.command --dry-run
```

完整填写校验平台资料，但不保存平台资料，也不改动基础资料：

```bash
./run.command --no-save
```

注意：单个平台的 `--no-save`、`--save-only`、`--save` 都不会填写或保存基础资料。全平台 `--no-save` 也不改动基础资料；全平台 `--save-only` 和 `--save` 会先填写并保存一次基础资料，再在同一编辑抽屉中依次切换抖音、淘宝、天猫、拼多多、微信小店、小红书和有赞，不在平台之间刷新页面。选择 `--save` 时，七个平台都会按配置精确选择店铺并提交；选择 `--save-only` 时均只保存不铺货。铺货提交后若出现“铺货中/铺货进度”弹窗，程序会点击“收起”（并以右上角关闭或 Escape 作为后备），确认遮挡消失后再进入下一平台；新阶段启动时还会清理上一次遗留的进度弹窗。

默认情况下，如果出现“同步至 ERP 系统资料”确认框，程序选择“跳过同步”，仅保存快麦通资料。需要同步时：

```bash
./run.command --sync-erp
```

使用其他产品：

```bash
./run.command --excel-url 'smb://gongxiang/共享文件/谭/products/其他产品/产品信息.xlsx'
```

## 安全机制

- 查询不到唯一款式编码时停止。
- SKU 图数量与第一规格值数量不一致时停止，防止颜色错配。
- 图片未全部上传或页面存在校验错误时不保存。
- 出现编码重复并要求创建新编码时停止，不自动确认。
- ERP/快麦通认证链未完成时停止，不在 SSO 中间页强制跳转。
- 每次运行的日志、保存前/后截图和结果保存在 `output/kuaimai/runs/`。
